Frontend terminology,

Libraries, frameworks, meta-frameworks, build tools, rendering strategies — what they actually mean and how they relate to each other.

UI libraries & frameworks
what you build components with
UI library
aka "frontend library"
Tools for building user interfaces. Handles how components render, update, and react to data changes. Does not decide routing, data fetching, or project structure — you wire those up yourself.
ReactSolidPreact
UI framework
aka "frontend framework"
Like a library but more opinionated. Built-in conventions for routing, state, and project structure. More decisions made for you — less flexibility, faster initial setup.
VueAngularSvelte
you use this
React
library, not a framework
Only handles the UI layer. You choose your own router, data fetching, state management. This is why meta-frameworks exist on top of it. Most widely used — ~40% of developers.
most widely usedlibrary only
Meta-frameworks & build tools
what structures a full app
Meta-framework
aka "app framework"
Sits on top of a UI library and adds everything it's missing: file-based routing, SSR, API routes, build optimization, deployment config. Turns a library into a complete application structure.
Next.jsRemixNuxtSvelteKit
you've used this
Next.js
React meta-framework — built by Vercel
Most popular meta-framework for React. Adds file-based routing, server-side rendering, image optimization, and API routes. Frontend and a lightweight backend in one project.
React + routing + SSRAPI routes built in

Vite
build tool — not a framework
A fast build tool and local dev server. Compiles, bundles, and hot-reloads your code. No opinions about routing or rendering. Think of it as the engine room, not the application.

Rendering strategies
how & where HTML gets generated
CSR
Client-side rendering
Server sends a nearly empty HTML shell. Browser downloads JS, runs it, builds the UI. Fast after initial load, slower first paint. What React + Vite does by default.
Vite + ReactCreate React App
SSR
Server-side rendering
Server generates full HTML per request. Faster first paint, better SEO. Browser then "hydrates" the static HTML with React so it becomes interactive. Good for dynamic, user-specific pages.
Next.jsRemix
SSG
Static site generation
HTML generated once at build time, not per request. Blazing fast for content that rarely changes. Not suitable for dynamic, user-specific data like saved trips or auth.

What this means for the parks app
The decision

Which setup makes sense here?

The parks app is dynamic and user-specific — saved trips, auth, real-time search. SSG is out. The real choice is how much structure you want up front vs how much you learn by wiring things yourself.

React + Vite + Express
Two separate projects. You wire every layer yourself. More to configure, but you understand every seam. Best for learning and interview prep.
Next.js ★
One project. File-based routing, API routes, SSR out of the box. Faster to ship, closer to real-world usage. The proxy can live as a Next.js API route.
React + separate Express
React frontend, Express backend, clearly separated. Good middle ground — learn the layers without setting up a full pipeline yourself.
