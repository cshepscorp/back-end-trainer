Under the hood:
V8, the event loop,
and built-in modules

Node.js isn't just "JavaScript outside the browser." It's a runtime built from three distinct layers — each doing a very different job. Here's what each one actually does.

1

V8 — the JavaScript engine

from Google / Chrome
What it is

V8 is Google's open-source JavaScript engine, written in C++. It was built for Chrome and is also used in Node.js. V8 is the thing that actually runs your code.

What it does

Parses your JavaScript, compiles it to machine code your CPU can execute, manages memory allocation, and runs the garbage collector to clean up unused objects.

// You write this JavaScript const add = (a, b) => a + b; console.log(add(2, 3)); // → 5 // V8 does this (simplified): // 1. Parses the source → Abstract Syntax Tree (AST) // 2. Ignition (interpreter) converts AST → bytecode, runs it immediately // 3. TurboFan (JIT compiler) watches for "hot" code (run many times) // 4. Hot functions get compiled to optimized machine code // 5. Future calls hit the machine code directly — much faster
V8's pipeline: parse → interpret → JIT compile hot paths
The key insight

JavaScript is not interpreted line-by-line like old scripting languages. V8 uses JIT (Just-In-Time) compilation — it compiles frequently-run code to native machine instructions on the fly. This is why modern JavaScript can be fast enough to run servers handling thousands of requests per second.

2

libuv & the event loop

Node's superpower
The restaurant analogy: Imagine a single waiter at a busy restaurant. Instead of standing at each table waiting for the kitchen to finish cooking, the waiter takes the order, submits it, and immediately moves to the next table. When the kitchen calls "order up," the waiter delivers it. One waiter. Many tables. Nothing blocks.
libuv

A C library that handles all async I/O operations — file reads, network requests, timers, DNS lookups. It talks to the operating system's async APIs and manages a thread pool for operations that can't be done asynchronously at the OS level.

The event loop

A scheduler loop that coordinates between your JavaScript code and libuv. When async work finishes (e.g. a DB query returns), libuv notifies the event loop, which queues the callback and runs it when the call stack is empty.

Non-blocking I/O vs blocking — the core difference
⚠
When the analogy breaks down The single waiter is great for taking orders and delivering food. But if the waiter had to cook the meal themselves, everything stops. CPU-heavy work — image processing, encryption, heavy math loops — blocks the event loop and stalls every other request. This is why Node is excellent for I/O-heavy workloads (APIs, databases, file serving) but not the default choice for CPU-intensive computation.
3

Built-in modules

batteries included
What they are

Node ships with a standard library of modules — available without installing anything. They give your JS code access to OS-level capabilities that browsers intentionally block for security reasons. You access them via require('module-name') or import ... from 'node:module-name'.

http / https
Create servers, make requests. The foundation Express is built on.
fs
Read, write, delete, and watch files and directories on disk.
path
Join, resolve, and normalize file paths safely across OS types.
crypto
Hashing, encryption, secure random numbers, HMAC signatures.
stream
Process data in chunks — files, HTTP bodies — without loading everything into memory.
events
The EventEmitter pattern. The backbone of Node's async model.
os
CPU count, memory info, hostname, platform — useful for scaling decisions.
child_process
Spawn system commands or other processes. Used for running ffmpeg, git, etc.
url / querystring
Parse and construct URLs and query parameters reliably.
// Example: reading a file with the fs module import { readFile } from 'node:fs/promises'; const data = await readFile('./parks.json', 'utf-8'); const parks = JSON.parse(data); // Your JS just read from the filesystem — impossible in a browser // Example: hashing a password with crypto import { createHash } from 'node:crypto'; const hash = createHash('sha256').update(password).digest('hex');
Built-in modules give you OS access the browser never could
V8

Compiles and runs your JavaScript. JIT compilation makes it fast. Also manages memory and garbage collection.

Event loop + libuv

Handles async I/O without blocking. One thread, non-blocking. Great for APIs and databases. Not for heavy computation.

Built-in modules

Standard library giving JS access to files, networking, crypto, and OS capabilities — no npm install required.
