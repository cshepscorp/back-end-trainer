The proxy pattern

Why your frontend should never talk directly to a third-party API, and how a backend proxy solves the problem cleanly.

Request lifecycle — every hop
🌐
Browser
React app
① search request
⑤ results back
⚙️
Your server
Express · key lives here
② NPS request + key
④ park data
🏞️
NPS API
api.nps.gov
① Browser → Server

User types a search. React sends fetch() to your server. No API key needed — the browser doesn't know the NPS API exists.

② Server → NPS API

Express attaches the secret API key from an environment variable and forwards the request to api.nps.gov.

③ NPS processes

NPS validates the key, queries their database, and prepares a JSON response of matching parks.

④ NPS → Server

Park data returns to your server. You can filter, transform, or cache the response before passing it on.

⑤ Server → Browser

Your server sends the clean response. React receives it and renders the park cards to the user.

Why it matters
With a proxy ✓

API key stays secret

The key lives in an environment variable on your server. It never touches the browser. Even if someone opens dev tools and reads every network request, they cannot find it.

Without a proxy ✗

Key is fully exposed

If the browser calls the NPS API directly, the key must exist somewhere in your JS bundle — visible to anyone who opens the Network tab or views source.

In code
// ✗ DON'T — key is exposed in the browser bundle const res = await fetch( `https://api.nps.gov/api/v1/parks?q=${query}&api_key=ABC123SECRET` ); // ✓ DO — browser only talks to your server const res = await fetch(`/api/parks?q=${query}`); // On your Express server — key is safe here app.get('/api/parks', async (req, res) => { const npsRes = await fetch( `https://api.nps.gov/api/v1/parks?q=${req.query.q}&api_key=${process.env.NPS_API_KEY}` ); const data = await npsRes.json(); res.json(data); });
The proxy in Express — key never leaves the server
Bonus benefits of the proxy

Security isn't the only reason to use this pattern

  • Caching — cache NPS responses so you're not hitting their API on every keystroke. Saves on rate limits, speeds up the app.
  • Transformation — reshape the NPS response before sending it to the client. Strip fields you don't need, rename keys, merge data from multiple sources.
  • Rate limiting — control how often clients can hit your endpoints, protecting both your server and the upstream API.
  • Error handling — if the NPS API is down, return a graceful fallback instead of letting a raw error hit the browser.
